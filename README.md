# SmartGuest on Google Apps Script + GitHub Pages

One backend (Apps Script, data in a Google Sheet) and one front end that runs **either**
inside Apps Script **or** on GitHub Pages — same code, same login.

```
GitHub Pages (web/)  ──fetch POST──▶  Apps Script Web App (gas/)  ──▶  Google Sheet (your data)
Apps Script page     ──google.script.run──▶  same functions
```

## 1. Backend (Apps Script)

1. Create a new **Google Sheet** (this is your database; keep it private to you).
2. In the Sheet: **Extensions ▸ Apps Script**. Delete the sample code, then add these files from `gas/`
   (use the **+** next to *Files*; name them exactly):
   `Db.gs`, `Auth.gs`, `Services.gs`, `Restaurant.gs`, `Outlets.gs`, `Inventory.gs`, `Setup.gs`, `Code.gs` (Script) and `Index.html` (HTML).
   Open *Project Settings ▸ Show "appsscript.json"* and paste in `gas/appsscript.json` (set your time zone).
3. **Project Settings ▸ Script properties ▸ Add**:
   | Property | Value |
   |---|---|
   | `ADMIN_USERNAME` | e.g. `admin` |
   | `ADMIN_PASSWORD` | 8+ characters, letters and numbers (removed automatically after setup) |
   | `HOTEL_NAME` | your hotel's name |
4. Select **`setupDatabase`** in the editor's function drop-down ▸ **Run** (approve the permissions).
   It creates all sheets, roles, payment methods and your admin user. Optional: run **`addSampleRooms`**.
5. **Deploy ▸ New deployment ▸ Web app** — *Execute as:* **Me**, *Who has access:* **Anyone**. Copy the URL ending in `/exec`.
   Opening that URL already gives you the full app (Apps Script mode).

> After changing any `.gs` file: **Deploy ▸ Manage deployments ▸ ✏️ ▸ Version: New version ▸ Deploy**. The URL stays the same.

## 2. Front end on GitHub Pages

1. Create a GitHub repository and push this folder (the `web/` folder is the site).
2. **Settings ▸ Pages ▸ Source: GitHub Actions**. The included workflow (`.github/workflows/pages.yml`) publishes `web/` on every push.
3. Open `https://<you>.github.io/<repo>/`. On first visit it asks for the **Web App URL** from step 1.5 (remembered in that browser).
   To skip the prompt for everyone, put the URL in `web/config.js`.

## 3. Changing the front end

Edit files in `web/`, then run `python3 tools/build.py` — it rebuilds `gas/Index.html` (the Apps Script copy) —
and paste the new `Index.html` into Apps Script. GitHub Pages needs no build.

## What is included (this first pass)

Login with roles/permissions · dashboard · rooms & room types · guests · reservations (availability, occupancy limit,
rate override with reason, change dates, reassign room, cancel) · front desk (arrivals, in-house, check-in with deposit,
check-out, night audit) · folio (charges, discounts, optional tax on rooms) · payments (idempotent, partial reversals) ·
housekeeping board · **restaurant** (tables, menu, orders, walk-in or charge-to-room settlement; checkout is blocked while a guest has unsettled orders) ·
**printable receipts and invoice** (restaurant sales print **2 copies** — customer and restaurant; every other receipt prints **1**; all end with
"Generated by SmartGuest · date · user") · reports (payments by method, charges by service, check-ins per room) ·
**Bar, Gift Shop, Business Centre, Salon, Spa, Laundry, Gym, Pool, Parking and Transport** (one-step sales, pay now or charge to a room, one-copy receipt) · **inventory** (stores, units, items, stock in/out/stock-take ledger, red/amber/green levels with a reorder alert) · **expenses** (categories, void with a reason, excluded from totals) ·
**monthly financial report** (this month vs last month, including check-ins per room) · users/roles · hotel settings · audit log. Business rules were ported from the PHP code, including: no negative charges (discounts only), nights posted once,
checkout blocked with a balance unless the user has `payments.checkout_with_balance`, **credit-balance prompt**, disabled users
signed out immediately, login lockout (5 tries / 15 min), and unified "invalid username or password".

## Not ported yet

Room service, laundry, pool, gym, transport, car rental, parking, events,

`payments.reverse` reverses directly; every reversal is audited) · rate plans · backup module

## Things to know

* **Security.** The Web App must be "Anyone" so GitHub Pages can reach it; every call except login needs a session token
  (12 h, stored in the browser's session storage, signed out on password change/disable). Anyone with *edit access to the Sheet or
  script* can read or change all data, so share them with nobody. Apps Script has no bcrypt, so passwords use salted, iterated
  SHA-256 (1000 rounds) — weaker than the PHP version: use long passwords.
* **Speed.** Each Sheet write takes a fraction of a second; a check-in with deposit touches ~10 rows, so expect a few seconds.
  Fine for a small hotel; very busy properties should move to a real database later.
* **Concurrency.** All changes run under a script lock, one at a time, with all checks done before the first write, so a refused
  action leaves nothing half-done. (Sheets has no rollback; a crash mid-write is the one case that could.)
* **Quotas.** Consumer Google accounts have daily Apps Script limits (e.g. ~6 h runtime, ~20k URL fetches); normal front-desk use is far below.
* **Time zone** is taken from `appsscript.json`; "today", nights and reports all use it.

## Updating from the first version

Replace the `.gs` files and `Index.html` with the new ones (new files: `Restaurant.gs`, `Outlets.gs`, `Inventory.gs`), run **`upgradeDatabase`** once (gives the existing
Manager and Front Desk roles the new restaurant/receipt permissions; the Super Administrator gets them automatically), then deploy a **new version**.
Optional demo data: **`addSampleRestaurant`** **`addSampleOutlets`** and **`addSampleInventory`**. New sheets are created automatically.

## Tests

`node tools/test.js` runs 38 scenario tests against a local simulator of Sheets/Lock/Properties (`tools/gas-mock.js`).
`node tools/devserver.js` serves `web/` and a fake `/exec` on :8123 for trying the screens locally
(set `localStorage.sg_url='http://localhost:8123/exec'`).
